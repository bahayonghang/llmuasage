# 优化用量概览布局与术语

## Goal

消除本地用量概览页在宽屏下由组合热力图造成的大片无意义空白，并统一看板中的用户可见术语，使布局在桌面与窄屏下都紧凑、清晰，中文界面不再混用含义不明的英文或同义词。

## Background

- 用户截图显示：`活动日历` 与 `星期与小时` 纵向堆叠在一个横跨整行的面板中，但两个图表的实际内容宽度有限，约三分之二面板宽度没有内容，视觉上像缺少组件。
- `src/web/shell.rs` 中 `.analytics-heatmaps` 面板包含 `#calendar-heatmap`、水平分隔线和 `#hour-of-week`；`src/web/assets/render/hour-of-week.js` 将小时热力图固定为 `489×155`，而父面板通过 `.wide` 横跨两列。
- 既有归档任务 `08-12-dashboard-wide-blank-layout` 只修复 Hero、热门会话和状态卡空槽；`src/web/mod.rs` 的 `overview_wide_layout_avoids_orphan_blank_columns` 也只覆盖这三项，没有覆盖组合热力图。
- 当前中文文案将同一 `source` 维度交替称为“来源”和“平台”，将 `cache_efficiency` 显示为含义宽泛的“缓存效率”，并保留 `all models`、`Worker`、`sync job`、`Activity`、`Optimize`、`Other` 等中英混排术语。
- 后端 `HomeOverviewSummary.platforms` 与 `by_platform` 的实际键是 `usage_event.source`；本任务只修正展示术语，不修改已发布 DTO、API 字段或存储契约。

## Requirements

### R1 宽屏热力图排版

- 在宽屏桌面视口中，将每日活跃度与每周活跃时段并排放在同一面板内，用纵向分隔线建立清晰分区，并让 7×24 小时热力图随其分区宽度伸展。
- 中等与窄屏保持纵向堆叠，分隔线恢复为横向；图表不得造成页面级横向滚动。
- 空态应填满自身分区的可用宽度，不再让整行右侧出现“缺少组件”式空洞。
- 保留两个现有 DOM 容器 ID、渲染生命周期、筛选交互、快照行为与数据契约。

### R2 概览术语一致性

- 统一概览摘要卡和元数据中的维度名称：用户可见文案使用“来源”，不再把 `source` 称为“平台”。
- 指标名称使用可判断的名词短语：如“会话数”“请求数”“Token 用量”“估算成本”“缓存读取占比”“同步游标”“最近失败”。
- 热力图、会话排行和每日趋势使用能描述数据含义的标题与辅助文字；事件计数在使用量场景中统一显示为“请求”。
- 保留 `Token`、`CSV`、`SQLite`、`USD`、`MCP`、产品名和真实命令名等必要技术名词。

### R3 全看板中文术语审计

- 审计 `UI_COPY_ZH`、`SHELL_COPY_ZH`、服务端 HTML 中文默认值和中文 CSV 表头，清理无必要的英文混排和不一致同义词。
- 中文界面中将内部实现词汇改为用户语言，包括但不限于：`all models`、`Worker`、`sync job`、`live`、`normalized`、`Activity`、`Tools`、`Optimize`、`Compare`、`Cost Explorer`、`Turns`、`Other`。
- 导航分组和功能名应准确描述用途：运行相关入口不称为“运营”，分析入口不使用含义模糊的“切片分析”。
- 英文文案与中文语义保持对称；仅在原英文也含糊或维度名错误时同步改进，不改变 i18n key。

### R4 文档与回归保护

- 更新中英文 Dashboard 文档中受影响的概览部件名称和说明。
- 增加布局契约断言，覆盖组合热力图的宽屏双栏、窄屏回退和小时图响应式宽度。
- 增加术语回归断言，至少覆盖“来源”“缓存读取占比”“每日活跃度”“每周活跃时段”“高用量会话”和中文模型占位词。

## Acceptance Criteria

- [ ] 在用户截图同级的宽屏视口下，组合热力图形成左右两个内容区，右侧不再存在贯穿整个面板的大块空白。
- [ ] 在中等和移动视口下，两个热力图纵向排列、内容不重叠，`document.body.scrollWidth` 不超过视口宽度。
- [ ] 7×24 小时热力图能利用分区宽度；分区小于图表最低可读宽度时只允许图表容器内部滚动。
- [ ] 中文概览不再显示“最高平台”“个平台”“缓存效率”“活动日历”“星期与小时”“热门会话”或 `all models`。
- [ ] 中文全看板不再显示上述无必要的英文实现术语；技术专名与命令名除外。
- [ ] `source`、缓存比例、事件/请求等术语与现有数据语义一致，API/DTO/数据库字段保持不变。
- [ ] 相关 Rust Web 测试、Dashboard Node 测试和文档构建通过。
- [ ] 最终在中文/英文、浅色/深色以及至少宽屏与移动视口完成视觉验收，无控制台异常。

## Out of Scope

- 修改查询、同步、解析、存储、API 路由或快照 DTO。
- 新增图表、指标、后端字段或生产依赖。
- 重做全站视觉系统、侧边栏信息架构或品牌标识。
- 改名已发布的内部字段 `platforms` / `by_platform`；展示层继续兼容现有契约。
