# 重设计高用量分析并修复 Token 用量构成

## Goal

让“用量概览”中的高消耗分析和 Token 构成真正帮助用户回答两个问题：

1. 当前筛选范围内，消耗主要集中在哪些可识别的工作会话；
2. 这些 Token 在输入、缓存读取、缓存写入、输出和其他未细分部分之间如何构成。

本任务只规划并实施这两个现有面板及其必要的数据契约、测试和文档调整，不重做整个看板。

## Background and confirmed facts

- 用户截图显示当前“高用量会话”以十行文本排行展示，主标签大量为 UUID、哈希或 `sess_*` 技术标识；数值虽然准确，但缺少长度编码和可识别的工作上下文，无法快速比较相对差异。
- `src/web/assets/render/top-sessions.js:30` 直接使用 `session_label || session_id` 作为主标题，并把 `session_id` 同时作为日志下钻键。当前显示层与内部身份键没有分离。
- `src/parsers/codex.rs:562-578`、`src/parsers/claude.rs:439-445,538-541`、`src/parsers/kimi_code.rs:515-520` 等路径会把文件名、UUID 或 session id 写入 `session_label`。因此 `session_label` 不能被普遍视为人类可读标题。
- `src/query/top_sessions.rs:63-84` 已聚合项目、来源、Token、成本、事件数和活跃时长，并在内部候选中持有首末时间，但首末时间尚未进入 `TopSessionRow` 响应。服务端三种排序、完整筛选和日志下钻语义已有契约，不需要重写查询体系。
- `src/web/assets/app.js:55` 将 `1d` 设为默认范围；`src/web/assets/render/trends-daily.js:47-52` 在该范围无条件丢弃已经加载的 `trends_daily` 行并显示提示空态。因此截图中的“每日 Token 用量构成”不是接口无数据，而是默认首屏被前端主动隐藏。
- `src/query/mod.rs:1199-1239` 的 `/api/trends_daily` 数据链已经按筛选和 IANA 时区返回每日输入、缓存读取、缓存写入、输出、权威总量、事件数和成本；默认 1 天范围无需新增后端端点。
- `src/web/assets/render/trends-daily.js:61` 目前用四个可见通道之和决定柱高，而项目 Token 契约要求总量以持久化 `total_tokens` 为准，且不得默认把诊断性 `reasoning_output_tokens` 再加到输出或总量（`.trellis/spec/llmusage/backend/token-accounting-contracts.md:35-37,173-176`）。对只提供总量或存在独立推理通道的来源，四通道之和可能小于权威总量；若不显示差额，构成图仍会看似缺数据。
- 归档任务 `08-03-dashboard-ready-widgets` 明确把 1 天范围设计为空态，归档任务 `08-03-dashboard-session-analytics` 明确采用 flex 文本列表；这两项是已实现的旧设计选择，不是当前数据层限制。
- 用户已确认继续按“会话”聚合：技术 ID 仅保留为精确日志下钻键；可视标签使用“项目 + Agent + 时间”。不改成项目聚合，以免与现有项目排行重复并丢失具体会话定位能力。

## Requirements

### R1 — 高消耗会话改为可比较的图表

- 将当前十行纯文本排行替换为横向条形排行图；条长必须按当前排序指标相对缩放，右侧保留精确值，不能只靠颜色表达差异。
- 保留 Token 用量、活跃时长、估算成本三种服务端排序和 current-generation/latest-wins 保护；切换指标后顺序、条长、数值和辅助说明必须同步更新。
- canonical `session_id` 只作为稳定排序、日志过滤和下钻键保留，不得出现在正常可视标签、辅助文案或 tooltip 中。
- 图表标签必须使用现有的非敏感工作上下文，并能区分同项目的多次会话；主标签优先使用项目名，副标签使用 Agent 展示名与当前时区下的起止/最近活跃时间。无项目时使用本地化的“{Agent} 会话”回退，不从 prompt、消息正文或原始 JSON 生成标题。
- 每一条仍可点击进入事件日志的精确会话过滤；可点击性必须通过按钮语义、焦点态和辅助技术文案表达，不能依赖 hover。
- 典型十行、长项目名、重复项目名、无项目、无来源、零值、极端值、loading、degraded、no-data 都必须有明确且紧凑的表现。

### R2 — Token 构成在默认 1 天范围显示真实数据

- 面板应改成范围感知的“Token 用量构成”，而不是在默认 `1d` 或单日自定义范围无条件显示提示空态。
- `1d`/单日范围：聚合已返回的日行，展示一条 100% 构成条与各通道的精确 Token、占比和总量；它回答“近 24 小时花在什么地方”，不重复上方短时总量趋势。
- `7d`、`30d`、`all` 和多日自定义范围：保留按本地日的堆叠柱时间序列，同时让图例、tooltip、轴和可见总量采用同一构成语义。
- 可见构成至少包含输入、缓存读取、缓存写入、输出，以及 `total_tokens - 四个已知通道` 的非负“其他/未细分”差额；该差额用于来源仅报告总量、独立推理通道或其他未归入四通道的 Token，不能被错误并入输出。
- `total_tokens` 是总量和占比的权威分母；不得以 `input + cache_read + cache_creation + output (+ reasoning)` 重算总量。若已知通道之和异常大于权威总量，必须进入显式数据质量降级，而不是绘制负值或静默改写总量。
- 只有筛选后权威总量确实为零时才显示 no-data；loading、请求失败、数据不一致和真实零数据必须使用不同状态。

### R3 — 数据契约与兼容

- `/api/sessions` 只增加图表标签所需的非敏感时间上下文字段；现有字段、三种排序、limit、完整 `QueryFilter`、canonical id 和日志联动保持兼容。
- `/api/trends_daily` 继续复用现有响应与时区聚合；除非实施前的契约测试证明必须增加明确的派生字段，否则“其他/未细分”在前端由权威总量与四通道计算。
- live 和 snapshot 使用同一渲染路径；旧快照缺少新增会话时间字段时必须得到无 ID 的可读回退，不得抛错。
- 两个面板继续进入共享 secondary lifecycle、请求缓存、AbortSignal 和 generation guard；不得增加独立裸 fetch 或新的前端依赖。
- 保持 `/api/sessions` 代表性热身请求不超过 400 ms、响应不超过 128 KiB；新增时间字段不能破坏既有性能预算。

### R4 — 视觉、响应式、双语与无障碍

- 复用当前 dashboard 的 Catppuccin 语义 token、mono 数据排版、现有 `.seg` 控件和 `DESIGN.md:258` 的 Data Bars 语言；不引入第二套卡片或图表视觉系统。
- light/dark × zh/en 均需完整；中文、英文的标题、维度、其他/未细分、状态和下钻辅助文案不得硬编码在渲染器。
- 桌面宽屏应利用面板宽度形成清晰比较；窄屏条形图不得产生页面级横向溢出，长标签应截断并通过可访问名称保留完整语义。
- 图表必须可由键盘访问；精确值、排序状态和会话下钻不能只存在于 pointer tooltip。颜色不能成为通道或排名的唯一识别方式。

## Acceptance Criteria

- [ ] AC1：默认 `1d` 且存在 Token 数据时，构成面板显示聚合构成图、权威总量和各通道数值/占比，不再显示“近 7 天开始显示”的替代空态。
- [ ] AC2：`7d`、`30d`、`all` 与多日自定义范围显示按本地日的堆叠构成；`1d` 与多日模式共享相同的五类通道定义和 tooltip/图例文案。
- [ ] AC3：含 `total_tokens > 四通道之和` 的 fixture 显示“其他/未细分”且各段合计等于权威总量；含 `四通道之和 > total_tokens` 的 fixture 显示明确降级状态。
- [ ] AC4：真实无数据、loading、请求降级和构成不一致四类状态可区分；真实零数据不绘制伪造占比。
- [ ] AC5：高消耗模块渲染横向条形排行；Token/时长/成本切换后服务端排序、条长、精确值和 `aria-pressed` 一致，同值排序仍由 canonical id 稳定决定。
- [ ] AC6：UUID、哈希、`sess_*`、`session_*` 和 canonical source-prefixed id 均不会出现在可视主副标签或 tooltip；它们仍可作为点击后的精确日志过滤键使用。
- [ ] AC7：同项目多会话、无项目会话和旧快照都能用项目/Agent/时间上下文得到可区分的可读标签；不读取或显示 prompt、消息正文、原始 JSON。
- [ ] AC8：点击或键盘激活任一排行条会进入 `#logs` 并只过滤该 canonical session；快速切换排序或全局范围不会让旧响应覆盖新状态。
- [ ] AC9：新增 Rust/Node 聚焦测试覆盖会话时间字段、标签回退、ID 不泄漏、条形比例、三排序切换、1d 构成、未细分差额、异常降级、旧快照和双语；相关测试与完整 `just ci` 通过。
- [ ] AC10：用同一代表性 fixture 提供 1440px 与 1920px 桌面 light/dark、zh/en 关键截图，以及 `<=720px` 窄屏截图；人工核对比较效率、截断、焦点、对比度、无 ID 泄漏和无页面溢出。
- [ ] AC11：实现前后 `/api/sessions` 热身后 p95/载荷仍满足 `<=400 ms` / `<=128 KiB`，并记录实际值；Token 构成不增加新的后端扫描。
- [ ] AC12：双语 dashboard 文档按实际行为更新，明确会话图的可视标签、日志下钻与 1d/多日 Token 构成差异；analytics CSV 的现有机器可读 session 字段不在本任务中改动。

## Out of Scope

- 从 prompt、消息正文、原始 JSON 或外部服务生成会话标题；新增 AI 摘要、会话重命名或持久化用户别名。
- 修改解析器的 token 归一化、重建历史用量、schema migration、定价或成本语义。
- 将会话排行改造成项目排行；项目排行已有独立面板，本任务不复制该聚合面。
- 重做全局筛选、短时趋势、贡献日历、事件日志表、侧栏或整个看板视觉系统。
- 改变 analytics CSV 的列结构或原始 session 字段；本任务只移除正常看板中的技术 ID 展示。
- 新增前端框架、图表库、网络字体、远程资源或运行时外部请求。
