# 优化 Dashboard 运行状态与事件日志

## Goal

让侧栏“运行状态”和“事件日志”与页面中的实际区块、滚动顺序和导航高亮完全一致；让运行状态成为紧凑、独立且易读的诊断区；让事件日志在保留游标分页和原始记录按需展开能力的同时，不再把主页面拉成长列表。

## Background

- 已确认用户运行中的 Dashboard 地址为 `http://127.0.0.1:37421/`，页面可正常加载且浏览器控制台没有 warning/error。
- `src/web/shell.rs` 的侧栏顺序是 `#cost` → `#status` → `#logs`，但主内容 DOM 顺序是 `#logs` → `#cost`，且 `#status` 嵌套在 `#cost` 的 `.cost-status-grid` 中，不是独立 section。
- 点击“运行状态”时，浏览器滚动到嵌套的 `#status`，其父级标题仍是“成本估算”；`src/web/assets/app.js` 的观察顺序又是 `logs` → `cost` → `status`，因此 hash、可见内容和高亮可能短暂或持续不一致。
- 在 1280×720 实测中，成本排行左栏高 318px，运行状态右栏高 1245px；右栏高度决定整行高度，造成左侧约 927px 的无内容区域。`.status-diagnostics-stack` 还固定为三列，但实际只有“诊断线索”和“最近失败”两个子区块，进一步压窄卡片并增加纵向换行。
- `src/web/assets/data/fetch.js` 固定向 `/api/logs` 请求 `page_size=50`；实测首屏渲染 50 条事件，`#logs` 高约 3897px。会话标识可达 64 个字符，当前表格没有对长字段做清晰的截断层级。
- `src/web/assets/render/logs-viewer.js` 已支持游标“加载更多”和按 event key 延迟读取原始记录；这些数据能力应保留。

## Requirements

### R1. 导航与页面结构一致

- `#cost`、`#status`、`#logs` 必须是三个同级的顶层 section，DOM 顺序、侧栏顺序和 IntersectionObserver 顺序统一为“成本估算 → 运行状态 → 事件日志”。
- 点击“运行状态”后，视口起点必须是带有“运行状态”标题和说明的独立区块，不得再显示“成本估算”作为该锚点的所属标题。
- 点击“事件日志”后，hash、可见区块和侧栏高亮必须一致；保留 `#cost`、`#status`、`#logs` 现有深链接。
- 中英文导航、区块标题和说明保持同步，不引入硬编码语言分支。

### R2. 运行状态布局

- 运行状态继续展示现有“诊断线索”和“最近失败”内容，不删除或改写历史运行记录，也不改变当前同步健康的权威语义。
- 桌面宽屏使用与两个实际子区块匹配的平衡双列布局；不得保留空的第三列，不得由成本排行与状态诊断之间的高度差制造大片空白。
- 卡片和失败记录需要有稳定的最小宽度、合理换行和一致间距；窄屏时按单列堆叠，不出现页面级横向溢出。
- 运行状态区块在历史记录较多时仍保持清晰的信息层级，原始错误和诊断数据不得扩散到侧栏 endpoint 卡片。

### R3. 事件日志长度与可读性

- 实时看板首批请求 20 条事件，而不是 50 条；继续使用现有 opaque cursor 获取后续记录，不改变 Rust 查询默认值、最大页大小或 API schema。
- 日志表格放入有明确高度上限的局部滚动容器，表头在纵向滚动时保持可见；“加载更多”只增加容器内记录，不再无限拉长整个 Dashboard 页面。
- 时间使用现有本地化日期时间 formatter 显示紧凑值，并通过 `title` 保留原始时间；长会话、模型和项目文本使用省略号控制列宽，并通过 `title` 提供完整值。
- 数字列保持右对齐和等宽数字；行 hover/focus、展开状态和原始记录区分清楚。已有可聚焦行应支持 Enter/Space 展开，且 `aria-expanded` 与实际详情可见性一致。
- snapshot 空态、筛选变化、会话跳转、并发代际保护、游标加载和原始记录延迟读取行为保持兼容。
- 720px 及以下允许表格在自身容器中横向滚动，但不得造成页面级横向溢出；触控目标和滚动区域可用。

### R4. 回归与验收证据

- 增加结构回归，固定三个运行区块的同级关系、顺序、标题和导航观察顺序。
- 增加前端回归，固定日志首批页大小、紧凑字段展示、键盘展开、游标追加和 stale generation 防护。
- 新增或调整的文案覆盖中文和英文；live/snapshot 共用同一 embedded shell/assets，不新增生产依赖。

## Acceptance Criteria

- [ ] 在 `http://127.0.0.1:37421/` 点击“成本估算”“运行状态”“事件日志”时，每个链接都滚动到同名独立区块，hash 与高亮一致，顺序与侧栏一致。
- [ ] 运行状态桌面布局不存在截图中左侧的大面积空白，也不存在仅因三列模板造成的空列；1440×900 和 2048×1120 下两个诊断子区块平衡排布。
- [ ] 390×844 下运行状态单列堆叠，事件日志局部横向滚动，页面与 footer 无横向溢出。
- [ ] 事件日志首次只请求并显示 20 条；日志区块高度被局部滚动容器约束，表头粘性可见，“加载更多”后页面总高度不随记录数线性增长。
- [ ] 64 字符会话标识和长项目名不会挤压 Token/成本列；完整值仍可通过 title 读取，时间显示为本地化紧凑格式。
- [ ] 鼠标点击及 Enter/Space 均可展开/收起原始记录，`aria-expanded` 正确；筛选、会话跳转、snapshot 空态和 stale request 防护无回归。
- [ ] 聚焦 Rust/Node 测试、`git diff --check`、完整 `just ci` 和本地浏览器多视口验收通过，控制台无 warning/error。

## Out of Scope

- 修改 `usage_event`、`run_log`、SQLite migration、日志导入或原始记录保留策略。
- 修改 `/api/logs` 的 DTO、cursor 编码、Rust 查询默认页大小或 public read-only 路由边界。
- 改变 `sync_command_center` 的当前同步健康语义，或删除历史 `serve aborted`、同步失败等诊断记录。
- 重做整个 Dashboard 导航、其他分析区块或全局表格组件。

## Constraints

- 不新增生产依赖。
- 仅触碰解决本任务所需的 shell、Dashboard assets、聚焦测试和必要规范。
- 保留用户工作树中的无关改动；实现前后检查最终 diff 范围。
