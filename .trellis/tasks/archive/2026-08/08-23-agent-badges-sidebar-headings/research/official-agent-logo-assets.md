# Official Agent Logo asset inventory

Retrieved: 2026-08-23

## Purpose and admission rule

This inventory identifies first-party authorities and currently visible vector candidates for the ten llmusage source descriptors. A repository license does not automatically waive trademark restrictions. Before copying an asset, implementation must pin the exact upstream revision or download version, record SHA-256 and usage terms, and confirm that the mark represents the named product rather than only its parent company.

Allowed sources, in order: official product repository, official product website/brand page, official publisher brand asset. Do not substitute Simple Icons or another third-party collection; do not generate, redraw, trace, recolor, crop, or vectorize a raster Logo. If a first-party SVG cannot be verified, stop at Gate A in `implement.md`.

## Theme and packaging consequences

- Prefer compact product marks over wordmarks. When upstream supplies true light/dark variants, register both; otherwise place the unchanged mark on a neutral badge tile instead of applying CSS filters.
- Every admitted SVG must be self-contained and pass the task's script/event/external-reference/`foreignObject` checks.
- Local filenames follow the source stable IDs. The catalog continues to take IDs and display names from `SOURCE_DESCRIPTORS`; this table controls only Logo provenance.
- All Logo files ship through the existing embedded asset manifest and static export. Runtime remote URLs are forbidden.

## Planning conclusion

Five sources have concrete first-party SVG candidates (`opencode`, `kimi_code`, `pi`, `omp`, `deepseek_harness`). Codex, Claude, Antigravity, Grok Build, and ZCode have verified first-party authorities but still require exact product-vector admission during implementation. This is an explicit pre-code gate, not permission to use an unofficial fallback.
