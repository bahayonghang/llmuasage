# 重设计 Agent 徽章与侧边栏分组标题

## Goal

在不重做整个网页看板视觉系统的前提下，将概览 Hero 元信息中的已注册 Agent 来源从斜杠分隔长文本改为清晰、可扩展、可辨认的徽章组，并强化侧边栏“概览 / 分布 / 运行”分组标题的层级感，让用户能更快扫读来源覆盖范围和导航结构。

## Background and confirmed facts

- 用户提供的当前深色主题截图将 Hero 元信息中的“数据来源”行标为主要问题区域；当前十个已注册来源以一段 `codex / claude / ... / deepseek_harness` 文本连续展示，长名称和下划线降低扫读效率。
- `src/web/shell.rs:45-49` 从 `registered_source_descriptors()` 生成 `data-supported-sources`，但只传稳定 ID；同文件 `src/web/shell.rs:92-140` 定义三组 `.nav-label`，并通过 `aria-labelledby` 关联各导航组。
- `src/web/assets/render/hero.js:30-37` 将来源 ID 用 ` / ` 拼接，`src/web/assets/render/hero.js:54-71` 再把来源数量和整段文本当作普通字符串写入 `.hero-meta-item .mono`；现有结构无法给单个来源提供独立样式或语义。
- `src/domain/source_descriptor.rs:43-164` 是来源稳定 ID 与展示名的权威注册表，当前包含 Codex、Claude、OpenCode、Antigravity、Kimi Code、Pi、Oh My Pi、Grok Build、ZCode、DeepSeek Harness 十项。徽章不能复制一份容易漂移的独立来源清单。
- `src/web/assets/base.css:29-36,112-119` 只为较早的八个来源定义身份色；`zcode` 与 `deepseek_harness` 尚无身份 token。`src/web/assets/components.css:1860-1881` 的来源着色只覆盖来源分布行，Hero 列表没有复用。
- `src/web/assets/components.css:40-47` 的 `.nav-label` 仅使用 10.5px、muted 色和大字距区分层级；`src/web/assets/layout.css:514-557` 在 `<=720px` 横向导航中隐藏分组标题，因此本任务的标题重设计主要服务桌面侧栏，不应破坏移动端折叠行为。
- 归档任务 `08-03-dashboard-visual-system` 曾将来源标记定为低调、非填充的 8px 彩色文字。用户本次明确要求“重新设计”，可替换该组件规格，但不自动授权整套色板、导航项或页面布局重构。
- 用户已确认采用各 Agent 的官方 Logo，并允许为此新增本地 SVG 资产；本任务不再采用字母标记或纯色点作为十个现有来源的主身份表达。

## Requirements

### R1 — Agent 徽章组

- Hero 的“数据来源”元信息必须把每个已注册来源渲染为独立徽章，而不是斜杠分隔的单字符串。
- 徽章数据必须来自来源注册表的稳定 ID 与展示名；新增来源时应获得可读的默认徽章，而不是依赖同步修改硬编码数量或整份前端来源列表。
- 保留当前“活跃来源数量”事实，明确区分活跃数量与注册来源总数；不得让徽章样式暗示未激活来源已经就绪或已产生用量。
- 十个当前注册来源均应有稳定的身份表达；不能只依赖颜色区分，且长名称在典型桌面宽度下应可读。未知来源必须有中性 fallback。

### R2 — 官方 Logo 资产与徽章视觉

- 十个当前注册来源必须各自使用对应项目或品牌的一手官方 Logo；Logo 只能来自产品官方站点、官方组织仓库或官方品牌资产页，不得用第三方图标包、AI 生成、手工仿制或未经来源核验的描摹版本替代。
- 官方 Logo 以项目本地 SVG 资产随二进制和静态导出一起分发，运行时不得访问远程 Logo URL。每个资产必须记录一手来源 URL、上游版本或提交、获取日期、许可证/商标说明和本地文件名。
- 所有 Agent 徽章共享一致的几何、排版和密度规则；Logo 保持官方比例、路径和颜色，不拉伸、不裁切、不擅自重绘，也不把十个品牌色扩散到徽章外的页面装饰。
- 深色与浅色主题都要保持文本、边框和焦点/悬停状态的可辨认性；颜色不得成为表达来源身份或可用状态的唯一通道。
- 徽章组允许换行，但不得横向溢出 Hero 内容列、挤压右侧状态卡或造成明显高度跳变；窄屏应自然重排或降级为紧凑列表。
- 若徽章为非交互元素，不得伪装成可点击筛选器；若实施时增加筛选交互，必须先回到规划阶段补充行为、键盘和状态验收，本任务当前不授权该扩展。
- 当前十个来源若有任一项找不到可合法采用的一手官方矢量资产，实施必须停在资产准入门，不得静默换成非官方 Logo；未来新来源才允许显示中性的通用 fallback。

### R3 — 侧边栏分组标题

- 重设计“概览 / 分布 / 运行”及其英文对应项，使分组边界比当前 muted 小字更清楚，但视觉优先级仍低于导航项文字和当前激活项。
- 保留现有三组导航的信息架构、i18n key、`aria-labelledby` 语义、锚点顺序和点击行为；不得借机改名、重排或新增导航项。
- 标题样式应与徽章使用同一套密度、字形或细节语言形成呼应，但不能把三个标题做成看似可点击的按钮。
- `<=720px` 的横向导航继续隐藏分组标题；中英文切换不能造成侧栏溢出或组间节奏失衡。

### R4 — 设计系统和兼容边界

- 复用现有语义 token、`data-theme`、`data-locale`、嵌入式资产清单与原生 ES module 架构；新增 Logo 资产必须走现有 `/assets/{*path}`、ETag、压缩和静态导出链路，并提供未知来源 fallback。
- 不引入前端框架、图标库、网络字体、远程图片或运行时外部请求。
- live 与 snapshot 共用同一套 shell/渲染行为；不能改变看板 API、SQLite、同步、导出数据形状或来源稳定 ID。
- 只更新与本任务直接相关的 `DESIGN.md` 组件契约；不顺带修复该文档中其他历史视觉方向冲突。

## Acceptance Criteria

- [ ] AC1：使用注册表中的十个当前来源生成 Hero 徽章组；页面 DOM 中每个来源都有独立语义元素、稳定 ID、官方 Logo 和可读展示名，未来未知来源有中性 fallback。
- [ ] AC2：活跃来源数量与注册来源总数表达无歧义；徽章不会把未就绪来源伪装成成功/在线状态。
- [ ] AC3：Agent 徽章在 light/dark × zh/en 四种组合下均清晰可辨，不仅靠颜色区分，并在 1280px、1440px、1920px 桌面宽度下不溢出 Hero 或挤压状态卡。
- [ ] AC4：在 `<=720px` 窄屏下，徽章组无横向页面溢出；侧边栏分组标题继续隐藏，现有横向导航和触控目标不回归。
- [ ] AC5：三个侧边栏分组标题具有可见但克制的层级强化；导航结构、文本、顺序、i18n 和 `aria-labelledby` 关联保持不变，标题不呈现交互假象。
- [ ] AC6：注册来源清单发生新增或顺序变化时，Hero 不需要同步修改一份硬编码清单即可渲染；新增来源至少获得中性徽章。
- [ ] AC7：针对 shell 元数据、Hero 徽章渲染、转义/fallback 和响应式/i18n 契约补充聚焦自动化检查；相关 Node/Rust 测试及完整 `just ci` 通过。
- [ ] AC8：实施完成后提供同一数据夹具的桌面 light/dark × zh/en 截图，以及一个 `<=720px` 窄屏截图；人工核对徽章换行、标题层级、对比度和无交互误导。
- [ ] AC9：十个官方 Logo 均作为本地资产出现在嵌入式 asset manifest 中，以 `image/svg+xml` 返回并可被静态导出；没有远程 URL、脚本、事件处理器、外部引用或 `foreignObject`。
- [ ] AC10：资产出处清单逐项记录官方来源、固定上游版本/提交或下载版本、获取日期、许可证/商标注意事项与校验摘要；Logo 保持官方比例和视觉内容，未用第三方或生成式替代物。

## Out of Scope

- 重做整个侧边栏、导航信息架构、品牌标志、Hero 标题、筛选栏、状态卡或其他看板组件。
- 修改来源注册、解析器、同步状态、活跃来源计算、数据模型、API 或数据库。
- 把徽章改造成来源筛选器、tooltip 菜单、状态开关或可配置主题系统。
- 运行时远程加载 Logo、使用第三方图标包、AI 生成 Logo、手工仿制/描摹缺失 Logo，或把品牌素材用作 llmusage 自身背书和联合品牌。
- 将现有来源分布、日志表和同步命令中心的所有来源文字统一迁移为新徽章；本任务只保证新身份 token/fallback 不阻碍后续复用。
